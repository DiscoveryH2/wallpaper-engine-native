# 让 Steam 上的游戏在 Mac 上也活得下去

上周我把 Wallpaper Engine 搬到了 Mac 上。整套是 Swift + Metal 重写的原生客户端，直接读本机 Steam 里已经装好的东西，创意工坊该浏览浏览、该订阅订阅、该下载下载，多显示器各管各的壁纸，体积 17 MB，MIT 协议。跑通那一下挺爽，爽完就开始琢磨：这套活儿能不能复制到别的游戏身上。

答案是能，但得有人先把坑标出来。

Steam 上挂着几千款只认 Windows 的玩意儿。Mac 用户的日常流程大概是：装个虚拟机或者 CrossOver，然后花两个小时在论坛里刨一个 2021 年的帖子，照着做，报错，再刨。运气好的进了游戏，运气不好的看完开场动画就卡在加载界面。哪些真能跑、跑起来是什么德行，全靠口口相传，传着传着就散了。

我想做的东西挺朴素：一份靠谱的清单，加一群真上手试过的人。

具体到每款软件，差别很大。Wallpaper Engine 属于硬骨头：它要贴在桌面层下面，要管多屏，还要蹭 Steam 自己的账号和下载队列，套壳之后每走一步都跟系统别扭。这类只能原生重写，费劲，但重写完了体验比 Windows 原版还利索。

更多的单机老游戏、独立游戏、小工具就好办些。Wine、CrossOver、Apple 的 Game Porting Toolkit 能把八成的活儿干完，剩下两成全在细节里：某一版得关掉 DXVK，某款游戏得手动改分辨率，某个手柄映射歪了，某个存档路径会炸。这些经验现在散在 Reddit、GitHub issue、B 站评论区，保鲜期大约半年。

还有一类怎么折腾都白搭：内核级反作弊、32 位老引擎、吃 DLSS 的那批。碰到这种，最有用的做法就是写一句「别试了，不行」，附上原因。社区里最耗人的环节，是翻半天帖子发现楼主欲言又止，让你误以为有戏。

所以我想要的产出是这样的：每款游戏底下几行实话，写的哪套工具链、什么版本、打了什么补丁、实测多少帧、在哪里崩、谁验的、哪天验的。能复现，带日期，随时欢迎被人打脸。

Wallpaper Engine 那个仓库就当模板摆着：纯原生实现，演示素材自己做的，直接复用 Steam 的登录态和下载队列，136 项测试在干净 clone 上全绿，已知毛病一条不落写在 README 里。目前 1 个 star，14 个采集号的 fork，场面相当冷清，但它确实能编译。

缺的人是这几种：会 Metal 和 AppKit 的，愿意在 Wine 和 GPTK 里泡着的，手里还留着 Intel Mac 的。以及最缺的一种，只想干一件事的人：试完之后把「我试了，卡在这儿」写清楚。这活儿听着最没技术含量，其实最值钱。

底线摆一下：盗版、搬工坊资产、绕反作弊，这些别碰。游戏到底能不能跑，最终是版权方和反作弊厂商说了算，这事儿我没法用漂亮话糊过去。

仓库在 github.com/DiscoveryH2/wallpaper-engine-native。想一起搞的，开个 issue，标题写你试过的那个东西加结论就行。
