# 让 Steam 上的游戏对 macOS 友好起来

上周我在 Mac 上把 Wallpaper Engine 跑起来了。不是用 CrossOver 包一层，是 Swift + Metal 重写的原生客户端：直接读本机 Steam 里装好的内容，创意工坊能浏览能订阅能下载，多显示器各设各的壁纸，17 MB，MIT。跑完之后我想的不是"又搞定一个"，而是这件事能不能规模化。

Steam 上有几千个只写了 Windows 的东西。Mac 用户的常规操作是装个虚拟机或者 CrossOver，然后花两小时在论坛里翻一个三年前的帖子。失败率高，成功了也常常是能开不能玩。没人把"哪些能跑、怎么跑、跑成什么样"认真记下来。

我想做的东西很小：一份可信的清单，加一群真试过的人。

把问题拆开，其实是三类，处理方式完全不同。

第一类，能包但不该包的。Wallpaper Engine 就是。它要挂在桌面层下面、要接多屏、要走 Steam 自己的账号和下载队列，套壳之后每一处都在跟系统打架。这类只能原生重写，代价高，但一旦重写好，体验比 Windows 原版还干净。

第二类，能包且好包的。大量单机老游戏、独立游戏、工具软件属于这类。Wine、CrossOver、Apple 的 Game Porting Toolkit 已经能处理八成的活，缺的是一个个具体的补丁和参数——哪个版本要关掉 DXVK，哪个要改分辨率，哪个手柄映射歪了，哪个存档路径会炸。这些东西现在散在 Reddit、GitHub issue、B 站评论区，半年就失效。

第三类，包不了的。内核级反作弊、32 位老引擎、依赖 DLSS 的东西。这一类的正确做法是明确写"不支持"，并说清为什么。论坛里最浪费时间的不是失败，是有人含糊其辞让你以为有戏。

所以社区要产出的不是"支持 macOS"的口号，是每个条目下面这几行：用哪套工具链、哪个版本、打了什么补丁、实测帧数多少、哪里会崩、谁验证的、什么时候验证的。可复现，带日期，能被人推翻。

Wallpaper Engine 那个仓库就是我想推的模板：不套壳、不搬运别人的资产、复用 Steam 自己的登录态和下载队列、136 项测试在干净 clone 上全绿、每条已知缺陷都写在 README 里。它现在有 1 个 star 和 14 个采集号 fork，很惨，但它能编译。

需要的人：会 Metal 和 AppKit 的，愿意趟 Wine 和 GPTK 的，手上还有 Intel Mac 的，以及只愿意做一件事的——把"这个我试过，不行，卡在这里"写清楚的人。最后一类最缺也最重要。

不做的：盗版、工坊资产搬运、绕过反作弊。能不能跑最终取决于版权方和反作弊厂商，这一点我不会拿话术糊过去。

仓库在 github.com/DiscoveryH2/wallpaper-engine-native。想一起干的开个 issue，标题写你试过的那个东西和结论。
